## 3. 数据格式说明

### 原始数据格式

每个场景为一个 CSV 文件，包含 50 帧数据（10Hz，共 5 秒）：
- **帧 0-19**: 历史观测（History，2 秒）
- **帧 20-49**: 未来预测（Future，3 秒）

CSV 列格式：
```
TIMESTAMP, TRACK_ID, OBJECT_TYPE, X, Y, CITY_NAME
```

其中 `OBJECT_TYPE` 包含三种：
- **AV**: 自动驾驶车辆（ego vehicle）
- **AGENT**: 需要预测的目标车辆
- **OTHERS**: 周围其他交通参与者

## 4. 清洗流程

### Step 1: 基本校验

- 检查 CSV 格式完整性（至少 5 列）
- 确认场景包含 AV 和 AGENT 两种对象类型
- 缺少任一 → 跳过该场景

**结果**: 全部通过，0 个场景被过滤。

### Step 2: 轨迹完整性检查

- 检查 AGENT 的历史帧数是否 ≥ 20 帧
- 不足 20 帧 → 跳过该场景
- 不足 50 帧的轨迹用最后一帧坐标补齐

**结果**: 全部通过，0 个场景被过滤。

### Step 3: 异常检测与修复

对每个 AGENT 轨迹，检测连续帧之间的异常：

| 异常类型 | 阈值 | 判定条件 | 修复方式 |
|----------|------|----------|----------|
| 速度异常 | 50 m/s (180 km/h) | 连续帧速度 > 阈值 | 标记，不修复坐标 |
| 帧间跳跃 | 5 m/帧 | 连续帧位移 > 阈值 | 用前一帧坐标填充 |

> 注：仅对时间间隔在 0.05-0.2s 范围内的连续帧进行检测，跳过有时间间隔的帧对。

**修复逻辑**:
```python
# 检测到跳跃时，用前一帧坐标覆盖当前帧
if displacement > 5.0m:
    xy[current_frame] = xy[previous_frame]
```

### Step 4: 场景分类

基于 AGENT 轨迹的朝向变化对场景进行分类：

计算方法：
1. 取轨迹前 10 帧的方向向量 `start_dir = pts[10] - pts[0]`
2. 取轨迹后 10 帧的方向向量 `end_dir = pts[-1] - pts[-10]`
3. 计算两向量的夹角 `heading_change = atan2(cross, dot)`

| 场景类型 | 判定条件 | 含义 |
|----------|----------|------|
| straight | \|heading_change\| < 15° | 直行 |
| left_turn | heading_change > 15° | 左转（逆时针） |
| right_turn | heading_change < -15° | 右转（顺时针） |
| complex | 5° ≤ \|heading_change\| < 15° | 复杂/缓弯 |

### Step 5: 坐标变换

**方案选择**: 经过 2000 样本对比实验，选择**方案 B（以 Agent 为中心旋转）**。

| 方案 | X 范围 (mean) | Y 范围 (mean) | 终点距离 (mean) | 结论 |
|------|-------------|-------------|---------------|------|
| A: 以 AV 为中心旋转 | 13.39m | 20.32m | 40.63m | 偏大（AV 距离远） |
| **B: 以 Agent 为中心旋转** | **14.24m** | **19.00m** | **29.41m** | **✓ 最优** |
| C: 仅平移 | 16.12m | 20.27m | 29.41m | 范围偏大 |

**方案 B 具体步骤**：
1. **平移**: 以 AGENT 在 frame 19（历史最后一帧）的位置为原点
2. **旋转**: 以 AGENT 在 frame 18→19 的运动方向为 x 轴正方向
3. 对所有坐标（AGENT、AV、OTHERS）应用相同的平移+旋转变换

**变换公式**:
```
angle = atan2(y[19] - y[18], x[19] - x[18])
x' = (x - x[19]) * cos(-angle) - (y - y[19]) * sin(-angle)
y' = (x - x[19]) * sin(-angle) + (y - y[19]) * cos(-angle)
```

## 6. 结果分析与结论

### 6.1 数据质量

- **数据完整性极高**: 245,414 个场景全部包含完整的 AV 和 AGENT 轨迹，无任何过滤
- **异常比例很低**: 速度异常仅 1.6%-3.2%，帧间跳跃也很少，说明 Argoverse 数据集质量很高
- **无静止车辆**: 所有 AGENT 都有明显移动，适合轨迹预测任务

### 6.2 场景分布特点

- **直行为主**: 约 67%-71% 的场景是直行，符合城市驾驶的实际分布
- **转弯占 ~24%**: 左转（11-14%）略多于右转（8-9%），可能与美国右行交通规则有关
- **复杂场景约 10%**: 包括缓弯、变道等，是预测难度最高的部分

### 6.3 坐标方案选择

方案 B（以 Agent 为中心旋转）的优势：
- 终点距离最合理（29.4m，对应 3 秒 × ~10m/s 平均速度）
- X/Y 范围均衡，有利于模型学习
- 以被预测目标为中心，语义最清晰

## 7. 输出文件说明

### 7.1 DenseTNT 格式: `data_cleaned/{train,val}/*.csv`

- **格式**: 无表头 CSV，每行 `TIMESTAMP,TRACK_ID,OBJECT_TYPE,X,Y,CITY_NAME`
- **坐标系**: 原始世界坐标（DenseTNT 模型内部有自己的坐标变换）
- **清洗**: AGENT 轨迹已修复跳跃，其他对象保留原始数据
- **用途**: DenseTNT 训练和评估

### 7.2 LSTM/Kalman 格式: `data_processed/{train,val}/*.npz`

- **格式**: NumPy .npz 压缩文件
- **坐标系**: Agent-centered 旋转坐标（方案 B）
- **包含字段**:

| 字段 | 形状 | 说明 |
|------|------|------|
| `scene_id` | int | 场景 ID |
| `hist` | (20, 2) | 历史轨迹（旋转坐标） |
| `gt` | (30, 2) | 未来轨迹（旋转坐标） |
| `hist_global` | (20, 2) | 历史轨迹（世界坐标） |
| `gt_global` | (30, 2) | 未来轨迹（世界坐标） |
| `cent_x` | float | 原点 x 坐标 |
| `cent_y` | float | 原点 y 坐标 |
| `angle` | float | 旋转角度（弧度） |
| `city` | str | 城市名 (MIA/PIT) |
| `scene_type` | str | 场景类型 |
| `is_stationary` | bool | 是否静止 |
| `speed_anomalies` | int | 速度异常点数 |
| `jump_anomalies` | int | 跳跃异常点数 |

- **用途**: LSTM、Kalman Filter 等需要归一化输入的模型

### 7.3 数据差异说明

两种格式的**清洗规则完全一致**（同一份代码处理），唯一区别是坐标系：
- `data_cleaned/`: 保留原始世界坐标 → DenseTNT 内部会自己变换
- `data_processed/`: 额外做了 Agent-centered 旋转 → LSTM/Kalman 直接使用
